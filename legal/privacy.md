## Lokale Verarbeitung

G-Code, STL, Slicerprofile, Einstellungen, Vorschauen und Berechnungen werden auf
dem verwendeten Rechner verarbeitet. Die Anwendung lädt Modelldateien nicht zum
Anbieter hoch. Sie verwendet keinen Analyse-, Werbe- oder Telemetriedienst.
Benutzerdaten liegen standardmäßig im getrennten Anwendungsordner unter
%LOCALAPPDATA%/RodeProjects/SacrificialTower; Exporte können an einem selbst
gewählten zulässigen Ort gespeichert werden. Lokale Dateien bleiben dort bis zur
Löschung durch den Benutzer beziehungsweise zur dokumentierten Cache-/Logbereinigung.

## Programmaktualisierungen

Die gebaute eigenständige Windows-Version prüft beim Start einen öffentlichen
GitHub-Kanal. Dabei erhält der beteiligte Netzbetreiber technisch insbesondere
IP-Adresse, Zeitpunkt und angefragte Ressource sowie die feste Kennung
„SacrificialTower-Updater“. Modellinhalte, Profile, Lizenzschlüssel oder eine
Benutzerkennung werden nicht mitgesendet. Nach Klick auf „Aktualisieren“ wird der
Installer von GitHub heruntergeladen. GitHub verarbeitet Verbindungsdaten nach
seinen eigenen Datenschutzbestimmungen: https://docs.github.com/site-policy/privacy-policies/github-general-privacy-statement.
Dies kann internationale Datenübermittlungen umfassen; der Anbieter erhält durch
die Anwendung keine individuelle Nutzungsstatistik dieser Abrufe.

Die Prüfung lässt sich vor dem Start mit der Umgebungsvariable
COOLING_TOWER_DISABLE_UPDATE_CHECK=1 unterbinden. Entwicklungsversionen aus Python
und der vorbereitete Store-Kanal aktivieren diesen Updater standardmäßig nicht.
Die vorgesehenen Aktualisierungsabrufe dienen der Bereitstellung aktueller und
sicherer Software; die abschließende rechtliche Einordnung des konkreten
Vertriebs erfolgt im dokumentierten Freigabeprozess.
